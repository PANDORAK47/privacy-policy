## 4. 핵심 결정 1가지 — "식품 원료 조회" 경로
현재 `app/mfds_api.py` 는 **식품안전나라 OpenAPI 패턴**으로 구현돼 있습니다:
`{base}/{인증키}/{서비스ID}/json/{start}/{end}[/{조건키}={값}]`, 응답 `{서비스ID:{RESULT,total_count,row[]}}`.

회사의 식품원료·성분 조회는 **`DATA_GO_KR_API_KEY`(data.go.kr REST)** 를 쓰므로, 둘 중 택1:

- **(A) 식품안전나라로 통일** — 해당 서비스의 `서비스ID`만 알면 됨:
  `.env` 에 `MFDS_SERVICE_KEY=<FSK_API_KEY>`, `MFDS_INGREDIENT_SERVICE_ID=<서비스ID>` 설정 → 끝.
- **(B) ⭐권장: 기존 `ifacs-unified` 가 쓰는 data.go.kr 엔드포인트 재사용** —
  이미 정상 동작하는 그 주소(예: `apis.data.go.kr/1471000/...` 또는 `api.odcloud.kr/api/...`,
  `serviceKey` 파라미터, `items[]` 응답)를 그대로 사용. `app/mfds_api.py` 의
  `_call()` / `lookup_ingredient()` **한 곳만** data.go.kr REST 형태로 분기/수정하면 됩니다.
  (`MFDS_*_QUERY_FIELD`, `_first()` 후보 목록은 env/코드로 조정 가능하게 이미 분리해 둠.)

> 어느 쪽이든 `api_selftest.py` 가 **실제 row 필드명을 출력**하므로, 그 이름에 맞춰 `_first()` 후보만 맞추면 됩니다.

## 5. 완료 기준 (acceptance)
- `python3 scripts/api_selftest.py 정제수` → `raw row[0] fields: [...]` 출력되고 `wrapped ... 'source': 'MFDS_API'`
- `POST /verify` 결과의 `ingredient_findings[].source == "MFDS_API"`
- 워크벤치(`http://localhost:8000`) 상단 배지가 **"실연동"**
- (확장) 첨가물/농약 MRL/회수 서비스ID도 채우면 해당 도구도 실데이터화
